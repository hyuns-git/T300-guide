# 05. FastAPI와 SQLite로 서버 만들기

명령줄로 조회하는 것을 넘어, 이후에 대시보드나 배송 작업 관리를 올릴 수 있는 서버를 만들어 둡니다. 웹 서버는 FastAPI, 데이터베이스는 SQLite, 둘을 잇는 라이브러리는 SQLAlchemy 2.x입니다. SQLite는 파일 하나가 곧 데이터베이스라서 따로 설치하거나 서버를 띄울 필요가 없고, 혼자 개발하는 단계에 맞습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `app/pudu.py` | 푸두 서버에 서명된 GET 요청을 보내는 클라이언트와 명령줄 도구 |
| `app/db.py` | SQLite 연결과 테이블 정의 |
| `app/main.py` | FastAPI 서버 |
| `tests/` | 서버와 클라이언트 테스트 |

## 실행

`.env`가 준비된 저장소 폴더에서 실행합니다.

```
uvicorn app.main:app --reload
```

브라우저에서 `http://127.0.0.1:8000/docs`를 열면 엔드포인트 목록이 나오고, 각 항목의 Try it out 버튼으로 바로 호출해 볼 수 있습니다. 종료는 CMD에서 Ctrl+C입니다.

## 엔드포인트

| 경로 | 하는 일 |
|---|---|
| `GET /health` | 이 서버가 떠 있는지 확인 (푸두를 호출하지 않음) |
| `GET /stores` | 매장 목록 |
| `GET /robots?shop_id=...` | 로봇 목록 |
| `GET /maps?shop_id=...` | 맵 목록 |
| `GET /points?sn=...` | 현재 맵의 지점 |
| `GET /position?sn=...` | 로봇 위치 |
| `GET /call-logs?limit=50` | 푸두로 보낸 요청 기록 |

설정이 비어 있으면 푸두를 부르는 경로는 503과 함께 "설정이 없습니다" 메시지를 돌려줍니다. 푸두 쪽 오류는 502입니다.

## 호출 기록 테이블

푸두로 나가는 요청은 성공이든 실패든 `call_log` 테이블에 한 줄씩 남습니다. 컬럼은 시각, 명령 이름, 파라미터, 성공 여부, 응답 코드, 메시지입니다. 키와 시크릿은 저장하지 않습니다. 나중에 로봇을 움직이는 호출이 생기면 "누가 언제 무엇을 보냈는지"가 이 테이블에 남아야 하기 때문에 처음부터 만들어 두었습니다.

데이터베이스 파일은 서버를 실행한 폴더에 `t300.db`로 생깁니다. 위치를 바꾸려면 `T300_DB_URL` 환경변수를 설정합니다(예: `sqlite:///C:/work/t300.db`). 테이블은 서버가 시작될 때 자동으로 만들어집니다. 테이블이 하나뿐이라 마이그레이션 도구는 쓰지 않았고, 테이블이 늘어나면 Alembic을 도입할 계획입니다.

## 왜 GET만 있나

이 서버에는 로봇을 움직이는 경로가 없습니다. 테스트 `test_no_route_can_move_the_robot`가 GET이 아닌 메서드가 생기면 실패하도록 막아 둡니다. 다만 GET이라고 해서 항상 안전한 것은 아닙니다. 푸두의 충전기 복귀 호출(`/open-platform-service/v2/recharge`)은 GET인데 로봇을 움직입니다. 그래서 이 서버에는 그 호출을 넣지 않았고, 움직이는 명령은 확인 절차가 있는 `app/move.py`([07](07-move-robot.md))에만 있습니다.

## 코드에서 짚을 곳

- SQLite 스레드: FastAPI의 동기 함수는 스레드풀에서 돌기 때문에 `connect_args={"check_same_thread": False}`를 줬습니다. 세션은 요청마다 새로 열어서 스레드끼리 공유하지 않습니다.
- 테스트: 푸두 서버는 가짜 객체로, 데이터베이스는 메모리 SQLite로 바꿔서 돌립니다. FastAPI의 `dependency_overrides`를 씁니다.
- 푸두 클라이언트는 첫 요청 때 한 번만 만들어 재사용합니다(`lru_cache`).
